## Gap testing, done before any plugin was written

The PRD §7.2 list of missing functions was a hypothesis. I tested it two ways against HyperFormula 3.4.0: first against the function registry, then by loading the whole workbook into stock HyperFormula (`useArrayArithmetic: true`) and running every assertion. **Stock HyperFormula passed 179/277.** Every failure traced back to one of the causes below.

| Function / behavior | PRD hypothesis | Finding | Fix |
|---|---|---|---|
| `AVERAGEIFS` | missing | **Missing** (`Forecast!L5:O16` → `#NAME?`) | plugin |
| `LOOKUP` | missing | **Missing**. `IFERROR` hid the `#NAME?` in `Book!F2`; the bank-rec cascade then failed (`BankRec!B10`–`B22`) | plugin |
| `INTERCEPT` | missing | **Missing** | plugin |
| `TREND` | missing | **Missing** | plugin |
| `FORECAST.LINEAR` / `FORECAST` | missing | **Missing** | plugin (with alias) |
| `TEXT` | missing | **Built in, but wrong:** `TEXT(100,"#,##0.00")` → `"100,##0.00"` | plugin override (SSF) |
| `INDEX(one-row range, n)` | not listed | **Wrong:** reads `n` as a row number and returns `#NUM!` (`Drivers!C9`, `E4:E6`, which cascades into rows 14–33 and `Checks!B9`) | plugin override |
| Bare `TRUE` / `FALSE` | not listed | **`#NAME?`**: HyperFormula only knows `TRUE()` (`Checks!B10`: `COUNTIF(B3:B9,FALSE)`) | config: named expressions `TRUE`/`FALSE` |
| Output rounding | not listed | **Default `smartRounding` keeps ~10 significant digits**: `Drivers!B21` = `691158.82747` vs `691158.827474712` | config: `smartRounding: false` |

These built-ins behave correctly and are not overridden: `SUMIFS` (including text-period criteria), `COUNTIFS`, `COUNTIF`, `SUMPRODUCT` with array power, `SLOPE`, `RSQ`, `EDATE`, `MONTH`, `MATCH`, `N`, `IFERROR`, `ROUND`, `AND`/`OR`, `ISNUMBER`, `ABS`, `AVERAGE`, `SUM`, `IF`.

## What works

- **Engine adapter** (`src/engine/`) implements the PRD §7.3 interface: `load`, `setCell`, `getValue`, `getFormula`, `fill`, `precedents`, `dependents`, `clone`, `undo`/`redo`, `exportCells`, plus `sheetNames` and `destroy`. HyperFormula stays behind the adapter; the rest of the app imports only `src/engine/index.ts`.
  - `{date}` constants load as 1900-system serials and export back as `{date}`. `exportCells()` right after `load()` deep-equals `workbook.json`: all 668 formulas round-trip verbatim, and text such as `"2026-08"` stays text.
  - `fill` uses HyperFormula's fill data and a single `setCellContents` call, so relative references adjust and one undo reverts the whole fill.
  - `dependents` follows references through ranges, e.g. `GL!E2` → `BvA!C6` (EN-6).
  - `clone` rebuilds from `exportCells()`, so experiments and hidden re-grading never touch the learner's engine.
- **Plugins** (`src/engine/plugins/`) follow Excel semantics and document their limits in each file header. `AVERAGEIFS` reuses HyperFormula's own criterion parser, so operators, wildcards, and coercion match its `SUMIFS`.
- **Grading helpers** (`src/grading/`): the PRD §4.4 comparison rules (assertion tolerance, experiment tolerance, `null`/`""` = empty, only full `YYYY-MM-DD` changes become dates), `checkAssertion`, `applyExperiment`, and `runExperiment` (on a clone). The verification page (M7) will reuse them.
- **Conformance suite** (`tests/conformance.test.ts`): one test per assertion (277) and per experiment (12). It also checks that the base workbook is unchanged after experiments, that no formula cell evaluates to an error, and that cells expected to be `""` are empty strings. It includes every targeted-semantics row of PRD §7.3.
- **`npm run verification:write`** turns the Vitest JSON report into `public/verification.json` (PRD §17.5), with engine version and plugin list. CI runs it after the tests and before the build. The file is gitignored because CI generates it.
- **Owner requests:** (a) `test:e2e` now fails fast if `dist/` wasn't built with the `/finance-excel-labs/` base (tested with a root-base build). (b) M0.md now records that PR #1 was merged and Pages is live.

## Decisions and changes made in M1

- **New runtime dependencies:** `hyperformula` 3.4.0 (GPL-3.0-only, per D1) and `ssf` 0.11.2 (Apache-2.0, named in PRD §4.3/§7.4). Their transitive packages are Apache-2.0 or MIT. `THIRD_PARTY_NOTICES.md` is regenerated.
- **Two built-ins overridden** (`TEXT`, `INDEX`). The PRD says not to override a native function that passes conformance; these two fail it. PRD §7.2/§7.4 are updated (v1.4).
- **Engine configuration:** `evaluateNullToZero: true`, so `=A1` on a blank cell is 0 as in Excel. `nullDate` 1899-12-30, which is exact for dates from 1900-03-01 on.
- **Formulas that reference unknown sheets are rejected** by `load` and `setCell` (OPEN_ISSUES #17). HyperFormula 3.4.0 throws an internal `Range does not exist` when such a cell is overwritten; I reproduced this while probing. Build mode will surface the error message.
- `TREND` supports only the single-value form and requires `known_x`. HyperFormula can't distinguish an empty argument (`TREND(y,,x)`) from a blank cell, and no lab formula needs the other forms (OPEN_ISSUES #18).
- `ssf` is imported as a default import, because Node's native ESM loader can't see its CommonJS named exports (Vitest hides this).
- **Test note:** `Forecast!N5` (named in the PRD §7.3 table) has no assertion of its own; only the ratios `O5:O16` are asserted. Its test checks N5 against a plain average of its input cells and checks the dependent `O` assertions.

- `verification.json` exists only in CI builds (and after running `verification:write` locally). The verification page (M7) must handle its absence in local builds.
- OPEN_ISSUES #15 (TypeScript pinned to 6.0.x) is unchanged.
